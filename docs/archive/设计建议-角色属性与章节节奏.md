# 设计建议：角色属性 + 章节节奏（VN 三机制落地）

> 目标引擎：`H:\AIgame\myAIgame`（事件溯源 + 单次同步 LLM + 异步副作用 + 预算纪律）
> 本文是对话建议的文字版，含可直接对照的代码接点。日期：2026-08-18

---

## 0. 一个统一判断

三个机制是同一件事：**状态归引擎、LLM 只写增量与表达**。

- 想法 1（内置属性）＝ 引擎拥有权威数值，LLM 只写有界增量。
- 想法 2（行为推导）＝ 规则层算「倾向」，LLM 演「执行」。
- 想法 3（章节节奏）＝ 框架是数据（状态条件），内容是自由。

引擎当恒温器 + 裁判；LLM 当作家 + 记账员。这与现有架构哲学（事件溯源唯一事实源、单次同步 LLM、有界增量）自洽。

## 1. 内置属性（每个角色一张表）

### 1.1 表结构

| 类别 | 例子 | 变化速度 | 喂给 LLM 的形式 |
|---|---|---|---|
| 能力值 | 智力/战力/感知 | 慢（重大事件） | 分带（高/中/低） |
| 关系值 | 好感/信任/态度 | 快（每次有效互动） | 分带 + 变化轨迹 |
| 身体状态 | 伤势/精力/体力 | 中 | 分带 |
| 私有心智 | 目标/秘密计划（已有） | 按回合 | 仅叙事者可见 |

### 1.2 规则

1. **LLM 只写增量，引擎 clamp + 记账**。复用 `ATTR_CHANGE` 模式（`world_state.py:140`：±3、0~100 夹逼），扩展到目标实体：`{entity, attr, delta, reason}`。
2. **每次变化带 `reason`**（"因事件#12 顶撞 → 好感 -8"），事件树展示因果。
3. **LLM 看到波段而非裸数字**：`对你好感：低（近因：昨日与首领争执）`。LLM 读梯度、引擎读数字。
4. **触发式更新，不每回合更新**：沿用 `WORLD_TICK_MIN_MINUTES=60` 阈值哲学（`config.py:22`），加 `significant` 标记。

### 1.3 代码接点

- 扩展 `npc_mind.update_minds` 的 JSON 契约（六合一）→ 新增 `NPC_ATTR_CHANGE` 事件
- `WorldState.apply` 增加 `NPC_ATTR_CHANGE` 分支（clamp + reason）
- `state_block`（`prompts.py:65`）按「在场 NPC」渲染分带属性 + 【关系读数】
- 事件树/人物页展示 reason；`drawer_snapshot` 只暴露玩家可观测部分（可分段）

## 2. 行为推导 + 性格演化

### 2.1 双保险

- **规则层（确定性）**：维护关系读数，阈值触发（低信任 + 近期冲突 → 背叛倾向）→ 注入 `state_block` 的【关系读数】段。
- **LLM 层（表达）**：拿到倾向 + 分带属性 + 剧情，写自然执行；不猜测"这人会怎么想"，只执行摆好的倾向。
- 规则层只做**闸门**（阈值→倾向），LLM 只做**表达**。仅靠 LLM 会漂移/好心，数字会变装饰；仅靠规则会僵。

### 2.2 三个时间尺度

| 尺度 | 粒度 | 谁更新 | 现有对应 |
|---|---|---|---|
| 关系值（好感/信任） | 回合级 | 每回合副作用 | NPC_STATE |
| 能力值/身体 | 事件级 | 重大事件 | ATTR_CHANGE |
| 性格演化 | 章节级 | 章节边界一次 | 新增（与章节收束同机） |

性格逐回合改 = 反应式、漂移快；章节边界 re-anchor = 慢变量，属性和剧情综合。

### 2.3 代码接点

- 新增规则表（配置驱动，非硬编码 if）：`trigger → 条件(属性读数) → 倾向文本`
- 倾向注入 `npc_section`/`state_block`，与 `witnessed_by` 隔离并存
- 章节边界由 `chapter_engine` 输出 `personality_drift: [{npc, delta, reason}]`

## 3. 章节节奏控制

### 3.1 章节 = 状态条件，不是剧情

```
CHAPTER 事件：
{index, title,
 time_scope: {start, max_minutes},   # 时间窗
 places: ["校园", ...],               # 地点范围
 goal_condition: "主角离开校园范围",   # 达成即收章（状态条件）
 pressure_text: "午夜前必须离开"      # 章节压力（复用 pressure 机制）
}
```

- 目标必须是**状态条件**（place/时间/物品状态），禁止「节拍条件」（"说服 Boss"）。
- prompt 只注入 `【本章范围】`，范围内完全自由。

### 3.2 防跑偏（不硬推）

- 软范围：叙事倾向把剧情往范围内引，通过压力而非封锁（`PLOT_PRESSURE` 升级为章节时钟）。
- 章节时钟（半硬）：章节内累计分钟超阈值 → `chapter_engine` 注入合理收束事件，防无限拖延。

### 3.3 章节结束管线（唯一新增的一次异步调用，不碰 1-sync 原则）

```
引擎检测 goal_condition（规则佐证 + meta 里 goal_progress 双确认，防早收）
→ 叙事器收【章节收束】块写尾声
→ chapter_engine（辅助模型，异步）：
   ① 章节总结 → 记忆金字塔 long/permanent 层
   ② 性格 re-anchor（想法 2）
   ③ 属性 re-anchor
   ④ 下一章框架：{时间跨度"三个月后", 地点集, 目标, 压力}
```

**下一章种子来源**：记忆里现成的 `open_threads` + `world_threads` + `main_plot`——记忆系统就是现成的前情提要机，不新造"写剧情"模块。

### 3.4 代码接点

- 新增 `CHAPTER` / `CHAPTER_END` 事件；`meta` 扩展 `goal_progress` 字段 + `normalize_meta` 校验
- `_side_effects` 增加 `chapter_engine` 分支（仅在章节边界触发）
- `_drain_side_effects` 边界放宽 90s 或拆两步（`game_session.py:247`）
- 前端：VN 阅读视图加章节横幅 + 目标行；事件树按章节分组

## 4. 实施顺序（各自独立可测）

1. **想法 1（属性）**——地基层。完成标志：角色卡有属性表、事件树显示「谁因何事变了多少」。
2. **想法 3（章节）**——与 `WORLD_TICK`/`main_plot`/`PLOT_PRESSURE` 同源，改动最小、收效最直观。
3. **想法 2（行为/性格）**——依赖 1，且 re-anchor 需要 3 的边界。

## 5. 三个坑

1. 数字漂移 → 必须有规则层 / 定时 re-anchor，否则好感度是装饰。
2. 章节「达成」不能只信 LLM 一个"是" → 用当前回合 place/物品/主线状态佐证，防早收。
3. 章节边界辅助调用偏重 → 放宽 drain 等待或拆分。
